Data Architecture & Schema SpecificationThe relational engine is constructed using SQLite for high performance, ease of backup, and minimal configuration overhead within a Replit container.3.1 Relational Database LayoutSQL-- Table: locations
-- Purpose: Houses the rigid geographic dataset across India
CREATE TABLE IF NOT EXISTS locations (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    city_name TEXT NOT NULL,
    state_name TEXT NOT NULL,
    city_slug TEXT NOT NULL UNIQUE,
    state_slug TEXT NOT NULL,
    region TEXT NOT NULL CHECK(region IN ('North', 'South', 'West', 'East', 'Central', 'North-East'))
);

-- Table: keywords
-- Purpose: Holds atomic components of the high-intent B2B search phrases
CREATE TABLE IF NOT EXISTS keywords (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    raw_phrase TEXT NOT NULL UNIQUE,
    niche_key TEXT NOT NULL,
    intent_type TEXT NOT NULL CHECK(intent_type IN ('wholesaler', 'supplier', 'manufacturer', 'importer'))
);

-- Table: programmatic_pages
-- Purpose: Operational routing engine. Holds pre-computed SEO titles, headings, and data relations.
CREATE TABLE IF NOT EXISTS programmatic_pages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    page_type TEXT NOT NULL CHECK(page_type IN ('city', 'state')),
    slug TEXT NOT NULL UNIQUE,
    title TEXT NOT NULL,
    h1_heading TEXT NOT NULL,
    niche_key TEXT NOT NULL,
    intent_type TEXT NOT NULL,
    target_city TEXT,
    target_state TEXT NOT NULL,
    region TEXT NOT NULL
);

-- Optimization Indexes for Instant Dynamic Route Matching
CREATE INDEX IF NOT EXISTS idx_pages_slug ON programmatic_pages(slug);
CREATE INDEX IF NOT EXISTS idx_locations_state ON locations(state_name);
3.2 Matrix Generation Scale LogicThe dynamic application footprint uses a structural logic mapping equation to control internal density and optimize crawl budgeting allocations.$$\text{Total Programmatic Pages} = (\text{Niches} \times \text{Intents} \times \text{Cities}) + (\text{Niches} \times \text{Intents} \times \text{States})$$Substituting the current operational database inputs:$$\text{City Pages} = 6 \times 4 \times 122 = 2,928$$$$\text{State Pages} = 6 \times 4 \times 36 = 864$$$$\text{Total System Pages} = 2,928 + 864 = 3,792 \text{ core targeting landing nodes.}$$4. Regional Partitions: Sitemaps are categorized by geographical direction (e.g., sitemap-north.xml, sitemap-south.xml, sitemap-west.xml, sitemap-east-central.xml).Size Constraint: Each file is capped at a maximum of 1,000 links to ensure fast processing times when search engine bots crawl the site.6.2 Internal Linking Lattice NetworkEvery programmatic page must avoid isolated routing paths. The engine dynamically queries the SQLite table during page assembly to construct two distinct structural navigation layers at the base of the layout:Intra-State Network Grid: The lower layout quadrant dynamically loops over and links to five neighboring commercial cities located within the same state.Example (on the Ludhiana page): Displays deep links to Amritsar, Jalandhar, Patiala, Bathinda, and Mohali.Cross-Intent Anchor Pairs: Every city page cross-links directly with its equivalent state-level category directory page to ensure clean anchor text distribution.Example: A page targeting a city links directly to its main state hub directory: /korean-jewellery-supplier-wholesale-suppliers-in-punjab.7.
